 1. High-Level Overview


  This project is a full-stack web application. "Full-stack" means it includes both a frontend (what the user sees and interacts with in their browser) and a backend (the server-side logic that handles data,
  database operations, and user requests).


   - Technology Stack:
       - Backend: Python with the Flask framework.
       - Database: MySQL for storing project details and contact messages.
       - Frontend: HTML for structure, CSS for styling, and the Jinja2 templating engine to dynamically generate HTML pages.

   - Core Purpose: To create a personal portfolio website where you can showcase your projects. It allows you to add and delete projects and to receive messages from visitors through a contact form.


  ---

  2. The Backend: How It Thinks (`app.py`)

  The app.py file is the brain and heart of your application. It runs on the server and responds to all user requests.


   - Flask Application: The line app = Flask(__name__) creates your web application.
   - Database Connection: The get_db_connection() function is a crucial helper. It reads your credentials from config.py and establishes a connection to your MySQL database. It's designed to handle potential
     connection errors gracefully.
   - Routes (URL Endpoints): Routes are functions that are tied to specific URLs.
       - @app.route('/'): The Homepage. When a user visits your main URL (e.g., http://127.0.0.1:5000), this function runs and simply displays the index.html page.
       - @app.route('/projects'): The Projects Page. This function connects to the database, fetches all records from the projects table, and then passes this list of projects to the projects.html template. The
         template then uses this data to display each project.
       - @app.route('/add_project'): This route cleverly handles two scenarios. If the user just visits the page (GET request), it shows the "Add Project" form. If the user fills out the form and clicks submit
         (POST request), it grabs the form data, connects to the database, and inserts a new record into the projects table.
       - @app.route('/delete_project/<int:id>'): This dynamic route allows you to delete a specific project. The <int:id> part captures the project's ID from the URL, and the function uses this ID to run a
         DELETE command in the database.
       - @app.route('/contact'): This route only listens for POST requests, which happen when a user submits the contact form. It takes the submitted name, email, and message and saves them to the contacts table
         in the database.

  ---


  3. The Configuration and Setup Files


   - config.py: This file's sole purpose is to keep your sensitive database credentials separate from your main application logic. This is a critical security practice. Your app.py imports this configuration to
     know how to connect to MySQL.
     install -r requirements.txt reads this file and installs them.
   - database_setup.sql: This is your database blueprint. It contains the exact SQL commands needed to create your database (dipak_portfolio) and the tables (projects, contacts) with the correct structure.

  ---

  4. The Frontend: What the User Sees (`templates` directory)


  The templates directory contains the HTML files. These are not static HTML; they are Jinja2 templates, which allows you to insert Python data and logic directly into them.


   - base.html: This is the master layout. It contains the HTML structure that is common to all pages, like the navigation bar and the footer. Other templates extend this one, ensuring a consistent look and feel
     without repeating code. The {% block content %}{% endblock %} is a placeholder that other templates fill in with their specific content.
   - index.html: The homepage. It extends base.html and fills the content block with all the sections: Hero, About, Skills, Certificates, and the Contact form.
   - projects.html: This is a dynamic page. It uses a Jinja2 for loop ({% for project in projects %}) to iterate over the list of projects passed from app.py. For each project in the list, it generates an HTML
     "card" with the project's title, description, and image.
   - add_project.html: This contains the simple HTML form for adding a new project.

  ---

  5. The Assets: Styling and Images (`static` directory)


  This directory holds all the files that don't need to be processed by the backend. The browser requests these files directly.


   - static/style.css: This is the stylesheet. It controls every visual aspect of your website—the dark theme, the gold accent color, fonts, spacing, layout, and the card design. It makes the HTML look good.
   - static/images/: This folder is where you store all your images (profile picture, project images, certificate placeholders). The HTML files link to these images using a special Flask function
     url_for('static', filename='...').


  Summary: The Request Lifecycle


   1. User Action: A visitor navigates to http://127.0.0.1:5000/projects.
   2. Backend Receives Request: app.py sees the /projects URL and triggers the projects() function.
   3. Database Interaction: The projects() function connects to the MySQL database and retrieves all records from the projects table.
   4. Templating: The function passes the list of projects into the render_template() function, pointing to projects.html.
   5. HTML Generation: Flask and Jinja2 work together. projects.html extends base.html, and its for loop generates the HTML for each project card using the data from the database.
   6. Backend Sends Response: A complete, final HTML document is sent back to the user's browser.

   7. Browser Renders: The browser displays the HTML and automatically requests the style.css file to apply the styling, making the page look exactly as designed.
